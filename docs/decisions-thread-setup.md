# Decisions thread: setup message

The pinned Decisions thread shows the decision queue as one live view with Waiting, Snoozed, Rulings and Recent tabs. It
never shows a card, so nothing in it blocks. Each question shows what the full queue page shows of it (its thread, age, what it blocks, context, evidence with captions, links, option details and any proposed ruling), then what can be done with it, all in place with no page change. Its options come first, as one choice list: each option is a row with its label and its detail in full, the recommended one tagged and chosen to start with. Picking a row sends nothing; the one filled button under the list names the chosen option and answers with it. With no recommendation nothing starts chosen and the button asks for a pick. Under that is one quiet row of the actions every card has, one tap each: Snooze 1h, with ▾ joined to it (the page's other times, each with when it returns: later today, tomorrow morning, next week, or a time of your own, filled in to start), Dismiss and Direction (it opens a note field in the card; Send is the next tap), then the Open the thread link. The card then says what happened, or shows the error. Snoozed questions are in the Snoozed tab beside Waiting, with when each returns and two pills: Bring back now and Dismiss. A builder's question card waiting in another thread is answered here too, with the same choice list and answer button, and the answer goes to the card in its thread. An approval, goal, secret or link card is shown with its options and command, and its one link opens that thread, where it is answered on itself. No link in the view opens the queue page or an item: a phone's in-app browser would open those without the page's cookie. To post the view again with no new question, run `chamberlain decisions repost`: it uses the same shell (with its height) and carries only the view key; never write the html by hand. `chamberlain ask` posts every new question there, and only there
(`threads.decisions` in `~/.config/chamberlain/config.json` names the thread): the live view when the queue page is up, or a one-line
notice when it is down. The page keeps the title at "Decisions · N waiting" once `decisionsServer` in the `web` section of `config.json` names
an orchestration:operate token.

Configure `models.decisions` in the existing `config.json` first, following [model configuration](MODELS.md). Run `chamberlain models selection decisions` and use the returned `launch.environmentId` and exact `launch.modelSelection`, including all options, when creating the thread through T3's existing launch tool. Resolve the project on that environment; if validation or the destination fails, stop with the work pending, with no alternate machine or model. Reuse the launch request id when reconciling an ambiguous result. After T3 confirms the launch, put its id in `threads.decisions` in the same configuration. Use the message below as its first message.

For an existing thread, use `chamberlain decisions repost`, including after `/clear`: it validates and applies the central selection before sending. Replace `<script address>` with the address inside the `<script src="...">` tag that `chamberlain web link` prints for your page (it is
`<base>/inline.js?view=decisions&amp;k=<view key>`; choose the listed base T3 can reach, or the `publicBase` when T3 is loaded over https). The key in it is the
**view key**, not the page's key: it can only read the queue and answer, snooze, direct or dismiss a question, because this message is copied into the thread. Never paste the page link or the page key
here: see [web-access.md](web-access.md).
