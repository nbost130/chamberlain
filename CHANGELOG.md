## [0.1.1] - 2026-11-12

### Fixed

- **The relay lock works on macOS.** The relay held its `flock(2)` on `chamberlain.db` itself, which on macOS conflicts with
  SQLite's own `fcntl` locks on the same file (on the BSDs the two kinds of lock interact; on Linux they do not), so the daemon was
  refused even with no other daemon running, and 32 tests failed there. The lock is now a `flock` on the state directory, which
  SQLite never locks. The handle is bound to both the directory's and the database's device and inode. A database with a second
  hard link is refused at start, since a link in another directory would sit under another directory's lock. A new test probes the
  platform's semantics and checks that the lock is taken and kept while the holder's own SQLite connection holds its locks.

## [0.1.0] - 2026-11-12

This is the first public version. It was extracted from a private working system; `docs/EXTRACTION.md` lists what was
removed and why.

### Added

- **The daemon.** It watches agent threads through an adapter and makes no model calls. It wakes one agent thread, the
  Steward, when another thread needs input, a run fails, or a turn ends by handing a question back.
- **Adapters.** The backend-agnostic core lives in `src/core/`, and each backend implements one contract
  (`src/core/adapter.ts`). T3 Code is the first adapter. An in-memory fake runs the test suite, and `docs/ADAPTERS.md`
  explains how to write a new adapter, with a sketch for herdr.
- **Delivery through a transactional outbox with one relay.**
  - Every producer only inserts outbox rows inside its own transaction, and only the daemon's relay sends them.
  - The relay holds a `flock(2)` lock on the database file, so a second relay on the same database is refused.
  - Outbox rows are immutable, and digest members are frozen when the digest is composed.
  - Attempts are counted before each send and capped, after which a row moves to a dead-letter queue and an alarm is
    raised. Delivered and cancelled ids leave permanent tombstones.
  - Every send carries a stable delivery id, so the receiver can de-duplicate.
  - `docs/ARCHITECTURE.md` states the exact guarantee and its remaining windows.
- **One SQLite database** in the XDG state directory (`~/.local/state/chamberlain/chamberlain.db`), in WAL mode with mode
  0600. Schema changes are versioned migrations, and a database from a newer version is refused at startup.
- **One item system.** Sweep findings, alarms, wake records and decision-queue questions share one table and one
  lifecycle (triggered, acknowledged, resolved). One function, with a repeat policy, decides whether an item notifies
  again. Each source can run in live, silenced or shadow mode.
- **The decision queue and the Decisions page.**
  - The page shows a ranked queue of questions, a mirror of cards waiting in other threads, and evidence files.
  - Answering a question writes its claim, its wake and any ruling in one transaction.
  - Inline frames may only read the queue, recent and rulings views, and answer a plain question.
  - Approvals use a two-step confirmation that the server checks.
  - The page binds only to loopback or Tailscale addresses.
- **The rulings ledger.** The Steward records proposals, which take force only when the operator confirms them, and
  rulings are cited by id.
- **Other Steward tools:** away mode, butlers, the Steward hand-off builder, the routine sweep with checks the operator
  defines, Steward health, queue-wait reports, `peek` and `t3x`.
- **A one-time importer** (`src/core/legacy-import.ts`) for the earlier file-based layout. It checks every record's
  version first and imports in one transaction.
- **A T3 compatibility check:** when a server is outside the tested range, Chamberlain warns but does not refuse.
- **Example configs**, systemd and launchd units, and templates for the Steward's commands and prompts.
- **Documentation:** the README (including the security model and compatibility), `docs/ARCHITECTURE.md`,
  `docs/ADAPTERS.md`, `docs/GLOSSARY.md` (every term mapped to its industry source), `docs/ROADMAP.md`,
  `docs/upstream-asks.md` and `CONTRIBUTING.md`.
